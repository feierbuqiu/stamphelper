# 贴票助手：网站设计与算法说明

更新时点：2026-07-31

> 本文是中文详细设计说明；仓库路径已按公开项目根目录整理。英文架构摘要见 [`architecture.md`](architecture.md)。

## 1. 交付结构

- `app/postage-data.json`：构建前从 `data/` 邮资总表和普通邮票面额源生成的静态数据。
- `app/destination-data.json`：构建前生成的国际国家／地区检索词、价区映射和包裹路向索引。
- `lib/stamp-solver.ts`：有限库存邮票组合求解器。
- `lib/stamp-solver.worker.ts`：把贴票方案与“足量”边界计算移出页面主线程的 Web Worker。
- `lib/stamp-profile.ts`：自定义纪特票、库存和主题偏好的本机持久化层。
- `lib/postage-calculator.ts`：邮政业务合法性和邮资公式层。
- `lib/destination-search.ts`：国际目的地模糊检索、可达性筛选和价区解析层。
- `scripts/stage-cloudflare-pages.mjs`：生成 Pages 静态目录，并校验带哈希 Worker 文件、内容及客户端引用。
- `scripts/security-policy.mjs`：根据最终静态 HTML 自动生成内联脚本／样式哈希和 Pages 安全响应头。
- `tests/`：求解器、邮资算例、静态数据完整性和服务端渲染测试。

站点不需要数据库、账号或网络 API 才能完成日常计算。自定义面额、库存与主题偏好会冗余保存在浏览器 `localStorage` 和 IndexedDB 中；它们不会上传，清除站点数据、更换浏览器或更换域名仍会丢失。旧版本的长效根路径 Cookie 只作一次迁移来源，读取后立即过期，避免把库存偏好附带到每个静态资源请求。

## 2. 普通邮票面额

页面从 `data/stamp-denominations.tsv` 去重后使用 17 种普通邮票面额，另内置 2.8 元和 8 元两种纪特票面额，共 19 种内置面额；金额一律换算为整数“分”：

```text
5、10、30、40、50、60、80、100、120、150、200、300、420、450、500、540、600 分
```

2.8 元纪特票默认足量；8 元纪特票默认库存为 `0`；17 种普通面额中的 5 分票也默认库存为 `0`。用户还可添加 0.01–200 元、精确到分的自定义纪特票，每台设备最多保存 20 种。所有面额进入同一个整数动态规划求解器，图案、票名和发行批次不参与组合计算。

## 3. 贴票方案的严格目标

给定应付邮资 `T`、面额 `v[i]` 和库存上限 `c[i]`，求非负整数 `x[i]`：

```text
S = Σ v[i] × x[i]
0 ≤ x[i] ≤ c[i]（“足量”面额没有有限上限）
S ≥ T
```

按以下字典序最小化：

1. `S−T`：先让溢价最小；因此可精确组合时必定选择 `S=T`。
2. `Σx[i]`：在相同总额下使用最少邮票。
3. 仅在前两项都相同的情况下，使用稳定的确定性方案，保证相同输入得到相同结果。

这不是“从最大面额开始拿”的贪心算法。某些有限库存条件下，贪心会错过张数更少的精确解；本站使用有界动态规划保证全局最优。

### 3.1 金额上界

如果最小可付总额为 `S`，从它的方案中移去任何一枚已用邮票后都必须低于 `T`，否则会存在更小的可付总额。因此：

```text
0 ≤ S−T < 当前可用的最大邮票面额
```

求解器只需搜索到 `T + max(v) − 1`，不需要无界向上枚举。

### 3.2 动态规划实现

求解器先除以当前可用面额的最大公约数，再对每个面额进行一次完全／多重背包转移。加入 1 分粒度的自定义票时最大公约数可降为 1，因此最坏计算规模会显著增大。

有限库存的转移使用按余数分组的单调队列，把朴素的 `O(金额 × 库存)` 降为：

```text
时间：O(面额种数 × 搜索金额)
空间：O(面额种数 × 搜索金额)（保存一组可回溯选择）
```

金额全程使用整数分，不使用二进制浮点金额做相等判断。方案与全部足量边界由 Web Worker 计算；极端任务运行期间主线程仍可响应，新输入会终止尚未完成的旧任务。

交互层不会为每次瞬时计算切换整张结果卡。输入变化后继续保留上一方案；只有请求超过 200 ms 才在固定尺寸区域显示“更新中”，结果返回后原位更新。首次尚无任何方案时才使用完整加载面板。这样既保留长任务反馈，也避免逐位输入产生标题闪烁和 24 px 布局跳动。

## 4. “足量”边界

“足量”不是固定 10 枚，也不是简单的 `ceil(T / 面额)`。

对面额 `i`，保持其他面额的当前库存不变，只把 `i` 临时改为无限库存并重新求全局最优方案。新方案实际使用 `i` 的枚数记为 `b[i]`：

```text
足量边界[i] = max(1, b[i])
```

含义是：在当前邮资和其他库存条件下，面额 `i` 达到这个数量后，再增加该面额也不能改进“溢价、张数”的最优结果。

交互规则：

- “足量”点减号：直接落到 `边界−1`，立即变成有限库存；
- 有限库存逐枚加减；
- 加到当前边界时自动折叠为“足量”；
- 邮资或其他库存变化时，所有边界随最优解重新计算。
- 推荐方案中的每个票面都可点右上角禁止符号，立即把该面额库存设为 `0` 并重新求解；
- 库存区既可逐面额“设为用完”，也可一键把全部面额设为 `0`；
- “恢复默认库存”会恢复各内置／自定义面额各自的默认值：2.8 元纪特票与大部分普通票为足量，8 元纪特票和 5 分普通票停用，自定义纪特票为足量。

## 5. 可贴票业务筛选

业务选择器只保留普遍服务柜台可办理、且可以进入贴票流程的基础产品；基础产品之间互斥，运输方式之间也互斥。

### 5.1 纳入

- 国内：信函、明信片、邮简、印刷品、盲人读物、义务兵免费信件、普通包裹；
- 国内市场产品：EMS、即日专递、标准快递、快递包裹，但必须录入普遍服务柜台本次显示的总价；
- 港澳台：信函、明信片、航空邮简、印刷品、盲人邮件、小包、M 袋、普通包裹、EMS；
- 国际：信函、明信片、航空邮简、印刷品、盲人邮件、平常小包、M 袋、国际包裹、EMS；
- 与基础产品相容的挂号、约投、回执和保价。

### 5.2 排除

- e 邮宝、e 特快等独立渠道产品；
- 协议客户代码、线上专线和平台专享产品；
- 2026-01-01 起停办的物品类国际挂号邮件；
- 把“国际平常小包 +16 元”人工拼成挂号小包的组合；
- EMS／包裹再叠加函件挂号费；
- 台湾给据函件加回执；
- 同一邮件同时选择航空、SAL 和水陆路。

若用户已经在柜台确认一个可贴票业务，但该业务没有全国静态价表，可切换“直接输入总额”。这条入口只负责邮票组合，不替用户判定协议渠道能否转到普遍柜台。

### 5.3 国际目的地检索与价区兼容

国际业务使用一个统一的可搜索组合框，同时容纳“具体国家／地区”和“直接按价区／组别计算”两种入口。显示名称以 `zh-CN` 简体中文为基线，并补充伊夫尼、中途岛、阿森松岛等无独立 ISO 两位代码的邮政地区：

- 支持中文常用名与正式名、汉语全拼和简拼；
- 支持英文常用名与正式名、ISO 2 位／3 位代码和常见别名；
- 支持常用简称及本土语言的 ASCII 拉丁字母写法，例如 `UAE`、`bohei`、`Nihon`、`Nippon`、`espanol`、`Deutschland`；常用简称优先于碰巧相同的 ISO 代码；
- 支持国际电话区号精确匹配，例如 `61`、`1`、`81`；
- 支持 `三区`、`第 3 区`、`3区`、`zone 3` 等直接价区输入；
- 默认先展示当前业务适用的全部价区，再展示常用国家／地区；
- 选中具体目的地后，界面显示其实际套用的航空／SAL 价区、其他函件组别、水陆路优惠属性或 EMS 区号。

检索完全在浏览器本地完成，不调用网络 API。国家选项会先经过当前“产品＋运输方式”的可达性筛选：SAL／水陆路未列入 2025 年 11 月第三方开通快照、EMS 静态表未列出、航空邮简选择非航空方式，或国际包裹当前运输方式没有对应路向时，页面会说明原因，不会悄悄回退到其他价区。朝鲜航空邮路保留可选但显示“不稳定”警告。邮路快照只作参考，收寄当日仍以营业系统或柜台为准。港澳台仍走独立业务区，不混入国际国家列表；国内本埠／外埠逻辑不变。

目的地索引保留营业系统中需要分别选择的同码条目。例如“美国本土外小岛屿”“中途岛”“威克岛”“约翰斯顿岛”各自显示；本地 `X-*` 代码只用于稳定区分，不会把具体地点折叠到上级属地。科索沃、阿克罗蒂里和泽凯利亚、克利珀顿岛、梅利利亚、锡金、休达不进入当前业务选择器。

## 6. 价格证据等级

页面不会把不同性质的数值混成“现行全国固定价”：

| 等级 | 页面标签 | 处理方式 |
|---|---|---|
| A | 现行公开价 | 直接按公开重量分档和附加费公式计算 |
| B | 指导价上限 | 显示计算上限，并提醒企业可以下浮 |
| C | 柜台／快照价 | EMS 使用带日期的标准字段快照；国内市场产品要求录入本次柜台总价 |
| D | 历史参考价 | 港澳台及国际包裹逐路向表明确标注 2021 参考，要求交寄前复核 |

香港水陆路包裹仍保留 D 类历史参考金额，但会明确提示“11185 目前不提供预估报价”，避免把历史金额误解为当前承诺报价。重量在界面中可用克或千克输入；千克小数先精确换算为整数克再进入现有计费分档，不按 11185 的显示方式截掉小数或预先整千克进位。

## 7. 静态数据完整性

构建前执行 `npm run data:generate`，并检查：

- 普通邮票去重后必须恰好 17 种面额；
- 内置面额总数必须为 19；2.8 元纪特票默认足量，8 元纪特票和 5 分普通票默认库存必须为 0；
- 国内普通包裹必须有 31×31＝961 个省级方向；
- 国际航空、水陆路、SAL 包裹分别必须有 230、134、116 条连续表记录；
- 国际检索索引必须恰好包含当前核定的 254 个国家／地区及邮政地区，显示名称不得混入繁体中文，六个已排除条目不得残留，并把可唯一识别的包裹路向关联到对应目的地；
- 源表中两个名称为空的航空路向保留为“源表名称缺失”并标为异常，页面不自动给出可交寄结论。

## 9. 安全模型

- 当前发布物是无数据库、无认证、无服务端写接口的静态站，因此没有可被跨站伪造的账户操作或服务端状态，传统 CSRF 在当前架构下不成立；以后加入任何写接口都必须重新设计 CSRF、CORS、认证和速率限制。
- 页面文本由 React 转义，不使用 `eval`、动态 `Function`、`javascript:` URL 或内联事件属性。唯一显式注入的主题启动脚本是编译期常量，不拼接用户／请求数据。
- 打包器对最终 HTML 中每段内联脚本和内联样式计算 SHA-256，CSP 不启用 `unsafe-inline` 或 `unsafe-eval`；同时限制对象、框架、表单提交、跨源连接、Worker 和媒体来源。
- Pages `_headers` 设置 `nosniff`、`DENY`、权限策略、无来源信息、HSTS、COOP／CORP，以及 HTML 重新验证和内容哈希资产一年不可变缓存。
- 自定义面额、库存、设备标识和主题在恢复时经过类型、范围、数量和长度校验；恶意修改本机存储最多影响该浏览器，且不会把任意字符串当作 HTML 渲染。
- 发布目录拒绝 `.env`、源码映射、`.openai`、数据库脚手架等非静态内容；依赖使用 lockfile 固定，并在发布前运行完整与运行时 `npm audit`。

## 10. 使用边界

- 贴票求解器单件金额上限为 20,000 元，覆盖当前表内最高 EMS 标准字段范围；
- 普通包裹 B 类数值是上限，不保证柜台一定收满；
- EMS C 类数值是 2026-07-30 查询快照，地区服务费、渠道折扣、计泡、临时停运和延伸服务可能改变实收；
- 国际包裹 D 类数值来自 2021 官方附件，只用于备票参考；
- 最终可交寄性和市场产品实收金额以收寄当日营业系统为准。
